### 2026-08-25 — 自動化資訊分享（規劃＋第一刀）

- 問題：希望把既有行程／風土／飲食自動發出分享，並問最終能否帶來收益
- 曾考慮：多平台 API 直接發文；站內上廣告／聯盟連結當第一收益；為流量改寫大量關鍵字頁
- 放棄原因：無社群 API 密鑰、未驗證頻道前自動發文易被判洗版；站定位仍是「真實走過的參考筆記」非電商／聯盟站（見 2026-07-25）；流量未起來前廣告傷害品牌且賺不到錢
- 現行方案：完整步驟見 `docs/automated-sharing-2026-08-25.md`
  - 結論：**可以帶來收益，但自動化發文本身不是收益**；收益＝被找到 → 被信任 → 才有可買的東西
  - 本站現況適合「原子化既有 JSON、半自動草稿、先做一個頻道」；67 則風土／飲食已夠用數月
  - 技術第一刀：`/feed.xml` RSS（給訂閱與 n8n／Make）；`npm run gen-share-pack` 產 Threads／LINE／IG 文案＋UTM；章節可深鏈
  - 明確暫緩：未人工審稿的多平台自動發、AdSense、未揭露聯盟、目錄農場
- 驗證：`npm run gen-seo` 產出 `public/feed.xml`；`npm run gen-share-pack` 寫入 `share-pack/`（gitignore）；build 後 curl feed、Hub 有 RSS 連結
